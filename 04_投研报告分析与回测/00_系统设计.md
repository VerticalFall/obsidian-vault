# 投研报告分析与回测系统 · 设计蓝图

> 起点：一个直觉 —— "卖方在牛市唱多、熊市看衰，本质是同一根行业食物链"。
> 这份文档做的第一件事，是用真实数据检验这个直觉，然后把它改写成**能被证伪的问题**。

---

## 一、先把直觉拆成三个不同难度的问题

原始想法里其实混着三件事，混在一起就没法做：

| | 问题 | 性质 | 数据量 | 可做性 |
|---|---|---|---|---|
| **Q1** | 卖方立场到底有没有预测力？谁有？在什么市场条件下有？ | 统计 | 年 1.6 万篇 | ✅ 立刻可做 |
| **Q2** | 他们当时看多的论据，几个月后成立吗？不成立时错在哪一环？ | 质化 | 精选数十篇 | ✅ 可做，需人工/AI 逐篇拆 |
| **Q3** | 立场本身是否被市场状态和利益结构系统性驱动？ | 元层面 | 年 1.6 万篇 + 状态标签 | ✅ 可做，是 Q1 的副产品 |

三者共用同一套采集与冻结层，但产出完全不同。**先做 Q1，因为它用一个月就能给 Q2 提供"该深挖谁"的筛选依据。**

## 二、数据先打脸：A 股卖方的"方向"是常数，不是变量

已实测（东方财富研报库，覆盖 49 家券商，2025-01-01 ~ 2025-12-31，**16,239 篇个股研报**）：

### 评级分布

| 评级 | 篇数 | 占比 |
|---|---|---|
| 买入 | 11,161 | 68.7% |
| 增持 | 4,147 | 25.5% |
| 未评级（港美股等） | 811 | 5.0% |
| 中性 | 89 | 0.5% |
| 持有 | 30 | 0.2% |
| **卖出** | **1** | **0.0%** |

> **偏多（买入+增持）= 94.2%。全年 16,239 篇里，"卖出"评级只有 1 篇。**

### 评级变动分布

| 类型 | 篇数 | 占比 |
|---|---|---|
| 维持 | 13,195 | 81.3% |
| 首次覆盖 | 1,935 | 11.9% |
| 上调 | 105 | 0.65% |
| 下调 | 105 | 0.65% |

### 结构化字段覆盖率

- 目标价：1,249 / 16,239 = **7.7%**（中文券商普遍不给目标价 → 目标价不能当回测主轴）
- 当年 EPS 预测：15,503 / 16,239 = **95.5%**（这才是好用的量化抓手）

### 结论一：直觉的后半句在 A 股不成立

"熊市集体看衰"这件事，在 A 股卖方评级里**几乎不存在**——因为不管牛熊，94% 都是买入/增持。评级方向不是一个随市场切换的变量，它是一个常数。

（头部机构更极端：民生证券 2025 年 1,422 篇，偏多占比 **100.0%**；东吴证券 2,156 篇，**99.8%**。）

### 结论二：但直觉的*机制*部分反而更值得测了

如果下跌市里买入评级依然是 94%，那评级就不是"预测"，而是"服务"或"默认状态"。
于是 Q3 变成一个非常锋利、可量化、且能出结论的问题：

> **当市场/个股已经在下跌时，卖方是"延后下调"还是"照常唱多"？这种粘性有多大？在粘性最强的机构上，后续收益是否更差？**

这个问题有数据支撑、有对照组、有明确指标（评级粘性 = 个股下跌后评级不上调/不下调的比例），而且能直接回答"是不是在帮主力出货"。

### 结论三：真正有信息量的四个维度

| 维度 | 为什么有信息量 | 数据来源 |
|---|---|---|
| **评级变动**（上调/下调/首次） | 只占 1.3%，是稀有事件 | 元数据 `ratingChange` |
| **EPS 修正方向与幅度** | 覆盖 95.5%，卖方唯一的连续可测输出 | 元数据 `predict*Eps` 跨期变化 |
| **唱多强度偏离**（个股唯一性） | 当全网都在唱多一只票时，新增唱多的边际信息递减 | 元数据聚合 |
| **论据可证伪度** | 论据里写没写可检验的数字/时点 | 全文拆解 |

### 结论四：拆解层跑完后发现的第五个维度 —— 「预测下调、评级不下调」

首批 5 条 claim 里，君亭酒店（华鑫证券，2025-09-15）是一个极端样本：

- EPS 预测从 **0.38 / 0.46 / 0.56 下调到 0.19 / 0.25 / 0.35**（2025 年利润预测**砍半**）
- H1 归母净利 −55%、扣非 −79%、Q2 扣非 −88%
- 正文标题自己写着"竞争加剧业绩承压"
- **评级：维持"买入"**
- 12 个月后：−37.42%，超额 −32.71%

于是得到一个能在元数据层**全量计算**的指标：

> **评级粘性 = EPS 修正幅度 与 评级变动 的脱钩程度**
> 做法：同一机构对同一股票的连续两篇报告，比 `predictThisYearEps` 的变化；EPS 下调 ≥30% 而评级仍为买入/增持 → 记一次"粘性事件"。

这个指标不需要读任何正文，就能在全量 1.6 万篇上统计，而且它直接对准"帮主力出货"的行为学假设。已排入 P2。

## 三、系统架构：四层 + 一条铁律

```
L0 采集与冻结      元数据 / 全文 / 行情 → 带哈希与时点，只增不改
      ↓
L1 量化回测层      全量立场 × 前向收益 × 基准 → 命中率 / 机构画像 / 状态条件
      ↓
L2 论据拆解层      精选报告 → 结构化论据 → 可证伪条件 → 到期逐条打分
      ↓
L3 输出层          单票研报史 / 机构可信度榜 / 公众号长文素材
```

### L0 · 采集与冻结

- **来源（已验证可跑）**
  - 元数据：`reportapi.eastmoney.com/report/list`（个股 / 行业 / 策略宏观，含评级、EPS 预测、目标价、评级变动、页数、作者）
  - 全文：`data.eastmoney.com/report/zw_stock.jshtml?encodeUrl=...`（正文 HTML，可直接抽）
  - 行情：`push2his.eastmoney.com/api/qt/stock/kline/get`（日线前复权，含指数）
- **冻结**：每条记录写入时附 `_frozen: {fetchedAt, source, infoCode}`，文件只追加不覆盖。
- **地位**：这是整个系统的地基。**没有冻结，后面所有复盘都不可信**——因为你随时能用"今天才知道的事"重写"当时的解读"。

### L1 · 量化回测层

单篇研报 → 一条可计算记录：

```
{ 机构, 作者, 股票, 发布日期, 评级, 评级变动, EPS 预测(当年/次年), 行业 }
  → T+1 收盘建仓 → 持有 21/63/126/252 交易日
  → 收益 - 同期沪深300 收益 = 超额
  → 按 评级 / 评级变动 / 发布时市场状态 / 机构 分组统计
```

输出：命中率、平均与中位超额、分布下沿（25 分位）、机构排行（含最差榜）。

### L2 · 论据拆解层（你说的"分析 skill"）

对精选报告做五步拆解，**输出必须是可机械判分的结构**：

1. **结论**：方向、目标价、时间窗（"未来 12 个月"还是"下半年"——很多报告根本不写，这本身就是发现）
2. **论据池**：编号列表，每条压成一句"因为 X，所以 Y"
3. **论据类型**：需求 / 价格 / 产能 / 份额 / 政策 / 成本 / 并购 / 新产品 ……（用于事后看"哪一类论据最常错"）
4. **证伪条件**（关键）：每条论据写一个"到期时可观测的判据"，例如
   > 论据：2026 年 HBM 出货翻倍 → 判据：2026 年报存货周转天数下降且毛利率 ≥ 45%；否则不成立
5. **逻辑链缺口**：论据到结论之间跳过了什么（这是事后复盘最有价值的部分）

### L3 · 输出层

- **单票研报时间线**：某公司历次研报立场、论据、后续结果
- **机构可信度画像**：谁的 12 个月超额最稳、谁的评级粘性最强
- **公众号素材**：可直接喂给 `wechat-writing` 技能的长文选题

## 四、五条不可违反的规矩

1. **冻结优先**：先落库原文与元数据，再做任何解释。原文哈希与抓取时点必须留痕。
2. **反前视偏差**：拆解只能使用发布日期当日及之前的信息。禁止用"后来股价走势"反推"当时论据强弱"。
3. **证伪条件前置**：复盘前必须已写好"什么算成立"。否则事后一定能把任何结果解释成"其实是有道理的"——这是这类系统最典型的失效方式。
4. **基线对照**：所有命中率必须配基准。A 股 2025 年普涨，随便唱多也能"对"；不比沪深300 的命中率没有意义。
5. **样本完整性**：不能用"我印象里的几篇报告"当样本。按机构×日期全量抽，并披露样本量与缺失率。

## 五、数据边界（诚实版，这一节很重要）

| 目标 | 现状 | 建议 |
|---|---|---|
| **A 股券商研报** | ✅ 元数据全量、全文可得、行情可得 | 主线，全部在这里 |
| **中金 / 中信等头部** | ✅ 同上 | 同上 |
| **高盛 / 摩根士丹利 / 野村** | ⚠️ 公开渠道只有媒体报道转述、摘要片段；完整报告在机构客户门户/Bloomberg/Wind 里 | 降级处理：只采"被公开引用的观点"（Reuters/彭博/FT/雪球等二手信源），**必须标注为二手**，不与一手研报混在一个统计口径里 |
| 港美股研报 | ⚠️ 东财有部分（`(空)` 评级的 811 篇里有一部分），字段稀疏 | 单列，不混算 |

**结论**：第一版不做外资行。理由不是不重要，而是拿不到全文的话，"拆解论据"这一步会退化成"复述新闻标题"，反而污染系统。外资行要单独做一个"二手观点追踪"薄层。

### 实测踩到的坑（重要，写下来免得重踩）

| 坑 | 现象 | 处置 |
|---|---|---|
| 东财行情接口 | `push2his.eastmoney.com` 对本机出口 IP 直接断连（web_fetch 侧可通） | 行情改用**腾讯** `web.ifzq.gtimg.cn`（前复权，800 根日线，含指数） |
| PowerShell 出网 | schannel 报 `SEC_E_NO_CREDENTIALS`，curl/Invoke-WebRequest 全废 | 一律用 **python urllib** 抓取 |
| 控制台编码 | 中文 print 触发 `charmap` 报错 | 跑脚本前设 `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8` |
| 研报正文只有摘要 | 东财正文页正文约 1,100–1,500 字（含主要观点/投资建议/风险） | 够做论据拆解；要全文需下 PDF（`pdf.dfcfw.com/pdf/H3_{infoCode}_1.pdf`），中文字体需 CID 解码，单独处理 |

| **P5 输出** | 单票时间线 / 机构榜 / 公众号长文 | 待办 |

### P0 跑完之后，设计要改的三件事

1. **主口径从"均值"改成"中位数 + 跑赢率"**：均值被右尾拉爆，12 个月偏多组均值 +14.76% 而中位 −10.98%。原设计里的统计口径已修正。
2. **"评级方向"从分析变量降级为背景常量**，真正的自变量是：评级变动、覆盖扎堆度、EPS 修正、评级粘性。
3. **新增一条主线假设**：`扎堆度 ↑ → 后续超额 ↓`。P0 已看到单调关系（同质样本 10+ 篇组中位超额 −22.19%、跑赢率 14.1%），P1 要做的就是用四年数据 + 行业中性化确认它是不是真的。
