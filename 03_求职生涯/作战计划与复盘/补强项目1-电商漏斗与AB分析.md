## 1. 为什么做（投递前要能一句话说清）

- 中文版简历技能区目前只有【AB 测试如已补学请加】占位 = 零痕迹；腾讯数分/宝洁 IT 类 JD 高频词：漏斗分析、A/B 测试、归因、提效
- 你没有真实业务 AB 数据 → 用**公开真实事件日志做分析 + 亲手设计并验证 AB 方案**，口径诚实且面试站得住
- 🔴 诚实红线：RetailRocket 无随机实验 → 简历/面试口径 =「漏斗分析 + 实验设计」，**绝不写"跑了真实 AB 实验"**；主动讲局限反而加分

## 2. 数据源（二选一，推荐 A）

| 源 | 内容 | 优点 | 代价 |
|---|---|---|---|
| **A. Kaggle · RetailRocket "E-commerce events history in electronics store"**（推荐） | 真实电商事件日志：view / addtocart / transaction，约 270 万条、2015-11 ~ 2016-04、visitor-id 粒度 | 免费即下、有完整浏览→加购→交易链、规模够做漏斗和分层 | 无 campaign/用户属性列 |
| B. BigQuery · GA4 演示库（Google Merchandise Store） | 会话级流量+转化+campaign 字段 | 有渠道/活动维度可做对比分析 | 需注册 GCP 免费层；口径偏 GA4 官方 schema |

选 A：下载 events.csv → 本地 MySQL 或直接 pandas 均可（个人项目用 pandas + parquet 更轻）。

## 3. 交付日历（5 个半天，不挤占投递与刷题）

| 天 | 模块 | 关键动作 | 产出 |
|---|---|---|---|
| D1 | 取数与清洗 | 下载 → 字段检查 → 缺失/重复 → 时间戳规范化 → **会话切分**（同一 visitor 间隔 > 30 min 记为新会话） | `events_sessions.csv`（会话级：visitor、起止、事件序列） |
| D2 | 漏斗主分析 | 会话级 **浏览→加购→支付** 三级漏斗；按周趋势 + 按品类/价格带拆解，定位最大流失环节 | 漏斗图 1 张 + 3 条发现 |
| D3 | 分层与对比 | 行为分层：仅浏览 / 加购未支付 / 成交；高意向未支付人群画像与**挽回价值量级**；成交 vs 未成交的 bootstrap 置信区间对比 | 人群画像 + 1 条可测建议 |
| D4 | **A/B 实验设计**（本项目的"AB 痕迹"） | 选 1 个可测干预（如购物车召回/运费策略）→ 定基线 p₀、MDE δ → 功效分析算最小样本量（α=0.05, power=0.8）→ **蒙特卡洛模拟验证**（np.random 双样本比例检验 ×1000 次，实测 power≈0.8） | 实验方案一页：指标、样本量、分流、陷阱清单 |
| D5 | 报告与简历化 | 一页结论页（漏斗图+发现+建议）；简历措辞；30 秒电梯陈述；模拟追问 5 连 | 报告 + 简历行 + 讲稿 |

## 4. CV 落点（中文版 · 项目经历区，D5 实测后填数字）

```
**电商用户行为漏斗与 A/B 实验设计**（个人项目，公开数据 RetailRocket ~270 万条事件）
- 清洗切分 ~XX 万会话（30 分钟无操作界定会话边界），搭建 浏览→加购→支付 三级漏斗，
  定位支付环节最大流失点（约 XX%）
- 分层对比高意向未支付与成交人群（bootstrap 置信区间），量化挽回空间，输出召回优先级
- 设计加购召回 A/B 方案：功效分析定最小样本量（α=0.05、power=0.8、MDE XX%），
  蒙特卡洛模拟验证功效达标；掌握实验分流与多重比较陷阱
```

英文版版面允许再加（伦敦 DS 岗可用 "experiment design & causal awareness" 措辞）。

## 5. 面试追问准备（D5 前过一遍，答不出就回去补）

1. 为什么观察性对比 ≠ 因果？你的"对比"里有哪些选择偏差？（换人必答）
2. 样本量公式里 p₀、δ、α、power 各是什么？MDE 设太小会怎样？
3. 多指标怎么防多重比较？（guardrail metric / 看板指标与决策指标分离）
4. 会话按 30 分钟切分的依据？换定义漏斗数字会怎么变？
5. 如果要做真实 AB，这个场景你会怎么分流、怎么避免网络效应污染？
