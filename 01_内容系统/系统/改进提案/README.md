# 改进提案

> PM（产品经理）角色通过规范性自检，对知识库整体（架构 / 链路 / 内容 / 查漏 / 功能升级）发现问题与改进方向，沉淀成提案文档。
> **DevOps 负责执行提案中的问题与方案，验证测试后回填状态**，PM 下次自检时复核，形成闭环。

## 目录约定

- 提案文件：`YYYY-MM-DD-改进提案.md`（按日期命名，一天一份，追加条目）
- 单条编号：`P-YYYYMMDD-N`（日期 + 序号）
- 提案类型：架构 / 链路 / 内容 / 查漏 / 功能升级
- 文件结构：头部**状态总览表**（≥3 条时，ID/主题/类型/优先级/状态）+ 提案明细（每条 = 要解决什么 / 方案 / 验收 / 验证 四字段，长文折叠，关键信息前置）——见 `2026-08-08-改进提案.md` 示例

## 状态流转

```
待执行 → 执行中 → 待验收 → 已验收
   │        │         │        │
   │        │         └── PM 复核不通过 → 回"执行中"继续
   └────────┴──── 方案不可行 / 放弃 → 已关闭（写理由）
```

| 状态 | 含义 | 谁负责 |
|------|------|--------|
| 待执行 | 已立项，等待执行 | DevOps 认领 |
| 执行中 | DevOps 正在实施 | DevOps |
| 待验收 | 已实施并自测，等复核 | PM |
| 已验收 | PM 复核通过 | PM |
| 已关闭 | 不采纳 / 不可行 / 放弃 | PM（写理由） |
