### P-20260807-01 · 全库定时远程备份（每周一随蒸馏）
- 类型：功能升级
- 现状与问题：C 盘重装导致非 git 内容全丢。目前只有「每日日报」子仓库有远程备份；书籍库、公众号输出、技能库、框架、图片等本地内容**没有任何远程副本**——再次发生磁盘故障即永久丢失。
- 影响面：整个知识库的持久性；本地资产（书籍/输出/技能/个人笔记）全部暴露在单点故障下。
- 改进方向与方案：
  1. vault 根目录新建独立 git 仓库（本地），仅作备份用；
  2. 忽略项：`01_内容系统/知识库/每日日报/`（自有仓库+远程）、`.obsidian/workspace*.json`、`.obsidian/cache`、`.claudian/sessions/`、`.claude/skills/`（junction 指向技能库本体，避免重复）；
  3. 远程：push 到现有私有仓库 `VerticalFall/obsidian-vault` 的 **`vault-backup` 分支**（与 main 隔离，不触发 Actions）；
  4. 新增 **weekly-backup** 技能：每周一随 weekly-distill 一起执行 `git add -A → commit → push origin vault-backup → 验证`。
- 优先级：P0
- 状态：待执行 →（本次执行）
- 验收标准：
  - 远程 `vault-backup` 分支存在，包含全库文件（除忽略项）；
  - weekly-backup skill 已创建，可一键完成备份+push+验证；
  - 本地备份仓库 `git status` 干净。

### P-20260807-02 · 书籍核心观点提炼 skill（诚实提炼，不绑定系统）
- 类型：功能升级（新增技能 + 模板修订）
- 现状与问题：现有「书籍模板」把「核心观点」与「写作可复用框架 / 关联选题与观点」绑死，10 本占位笔记核心观点全部是 `（待补）` 的系统化标签，缺少提炼方法论，容易为适配选题池而**扭曲作者原意**。
- 影响面：书籍库质量与写作信源的可信度；错误的核心观点会被 router/写作反复引用。
- 改进方向与方案：
  1. 新增 **book-summary** 技能：独立、诚实地提炼「这本书 / 这个作者想表达什么」——写作动机、核心思想（用作者自己的话优先）、支撑论证与关键概念、可引原句、诚实标注边界与争议；
  2. **不绑定系统**：提炼时不强行对接 `_观点.md` 锚点 / 「写作可复用框架」，系统侧衔接改为可选最后一步；
  3. 修订 `书籍模板.md`：把「作者的」核心观点放首位，「与选题/观点相关」降为可选。
- 优先级：P1
- 状态：待执行 →（本次执行）
- 验收标准：
  - book-summary skill 已创建（技能库 + junction 可见）；
  - 书籍模板已修订，核心观点面向作者原意、系统绑定字段可选；
  - 用该方法可对任意书产出诚实摘要（无"为系统强扭"的痕迹）。
