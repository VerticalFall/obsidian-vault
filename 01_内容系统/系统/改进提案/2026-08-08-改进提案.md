### P-20260808-01 · 微信 AI 机器人（CowAgent + GitHub MCP，读取全部 / 写入收件箱）
**功能升级 · P1 · ⏳ 待验收**（交付物完成 2026-08-08；部署到朋友服务器为用户侧操作）

- **要解决什么**：知识库只在 PC 本地可读写，人不在电脑前无法查询/记录；远程备份单向 push，无远程入口（观测）。
- **方案**：① 部署 CowAgent（chatgpt-on-wechat v2 继任）到朋友内网服务器，接个人微信——手机/PC 无需访问该服务器，同步走 GitHub 中转 ② GitHub 集成 = 官方 MCP server（零代码，配置 `~/cow/mcp.json`）③ 凭证 = 细粒度 PAT，仅授权 `obsidian-vault` 单仓库 ④ 写入沙箱 = 技能层约束：路径必须以 `01_内容系统/系统/inbox/` 开头、命名 `微信-YYYYMMDD-HHmm.md`、inbox 外一律拒绝 ⑤ 模型 = DeepSeek V4 Flash（控制台直配）。
- **验收**：① 微信查《漫步华尔街》核心观点返回内容 ② "记下某想法" → 远程 inbox 新文件 → 同步回本地可见 ③ 负测试：让机器人修改 inbox 外文件 → 被拒 ④ PAT 审计为单仓库。
- **验证**（08-08）：交付物完成——`01_内容系统/系统/机器人/README.md` + `部署指南.md`（阶段 0-5 + 验收测试表 1-5）+ mcp.json 配置 + 收件箱技能提示词；待用户按指南部署后回填。

<details><summary>用户已拍板决策 · 选型结论 · 方案细节 · 风险标注（点击展开）</summary>

**用户已拍板**：① 载体 = CowAgent（chatgpt-on-wechat v2.0 继任）；② 权限 = 读取全部 + 写入收件箱；③ 运行环境 = 朋友内网服务器（手机/PC 不挂其 VPN）；④ 模型 = **DeepSeek V4 Flash**；⑤ 收件箱 = `01_内容系统/系统/inbox/`；⑥ 同步时间点 = 沿用现有节奏（13:00 + 登录时）；⑦ 能力边界不变。

**载体选型结论**（用户选定，PM 评估合适）：CowAgent 是 chatgpt-on-wechat 官方继任，国内生态最成熟；原生支持微信渠道 + 插件/工具系统 + MCP 协议；支持 Linux 一键脚本 / Docker。

**方案细节**：
1. 机器人服务器只需出站访问 `api.github.com` + 大模型 API，与 VPN 无关；
2. 个人微信渠道基于第三方协议 hook（封号风险，见下）；
3. PAT 权限仅 Contents 读+写，其余一律 No access；
4. 诚实标注：MCP 写入权限是仓库级，GitHub 侧无法限制到 inbox/ 路径——沙箱为提示词级；需硬沙箱可后续自写 Python 工具插件；
5. 收件箱在 vault-backup 备份范围内、不在每日日报子仓库内；机器人写入内容每日随 P-02 同步回本地，确认后入库；
6. 机器人能力边界：查询笔记 / 搜索知识库 / 汇报系统健康（读 `_告警摘要.md`）/ 记想法到收件箱；不修改既有笔记。

**风险与诚实标注**：
- **个人微信封号风险**：第三方 hook 协议违反微信用户协议，用户已知情选择；备选企业微信官方渠道随时可切换；
- **Agent 模式 token 消耗**：比普通对话耗 token，按量计费需预算；
- **朋友服务器可信环境**：CowAgent 官方提示"仅在可信环境部署"——凭证最小化 + 收件箱沙箱缓解；部署前确认服务器出站可达 github.com；
- **未核实项**：个人微信登录方式细节（扫码/hook 协议版本）需部署时按其文档核实。

### P-20260808-02 · 知识库每日双向同步（本地 ↔ vault-backup）
**链路 · P1 · ⏳ 待验收**（已实施并验证 2026-08-08，验收 1/2/4 通过，验收 3 观察中）

- **要解决什么**：vault-backup 仅每周一由 weekly-backup 单向 push；远程产生的改动（机器人收件箱、手机端）无机制回到本地；冲突策略无约定（观测）。
- **方案**：① 新增 `01_内容系统/系统/scripts/sync-vault.ps1`：`pull --ff-only` → 有新内容则 `add -A && commit && push` → 全程日志 ② Windows 计划任务：每日 13:00 + 登录时（与 pull-reports 同机制：StartWhenAvailable）③ 冲突策略：本地为权威——`--ff-only` 失败则 stash → pull → pop；仍冲突则中止并告警，绝不自动覆盖任一方 ④ weekly-backup 技能降级为手动快照兜底 ⑤ 每日日报子仓库不受影响。
- **验收**：① 本地改文件 → 任务 push → 远程 vault-backup 可见 ② 远程提交 `inbox/` 文件（模拟机器人）→ 任务 pull → 本地可见 ③ 连续 3 天无人干预跑通、日志无异常（⏳ 观察中）④ 人为制造冲突 → 任务中止告警、零数据覆盖。
- **验证**（08-08）：sync-vault.ps1 已建（UTF-8 BOM，避免 PS 5.1 中文解析问题）；计划任务 `ObsidianVault-SyncVault-13h` / `-Logon` 已注册；inbox 目录已建（含 README 约定）；日志已 gitignore；实测本地→远程 `fdc7b0b..30a1ad0`、远程→本地拉回成功、冲突测试 FATAL exit=2 零丢失。
