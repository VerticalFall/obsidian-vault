# 微信 AI 机器人（CowAgent + GitHub）

> 目标（P-20260808-01）：在**朋友的内网服务器**部署 CowAgent，接个人微信；机器人通过 GitHub 备份仓库远程读写知识库，随每日同步（`sync-vault.ps1`）与本地保持双向一致。
> 部署操作见 [[01_内容系统/系统/机器人/部署指南.md|部署指南]]；本文件是模块总览。

## 架构

```
微信 ──► CowAgent（朋友内网服务器）
            │  出站：api.github.com（GitHub MCP）+ api.deepseek.com（DeepSeek V4 Flash）
            │  凭证：细粒度 PAT（仅 VerticalFall/obsidian-vault 单仓库）
            ▼
      GitHub 备份仓库（vault-backup 分支）
            ▲
            │  每日 13:00 + 登录时：sync-vault.ps1（pull → push）
            ▼
      PC 本地 Obsidian Vault（01_内容系统/）
```

要点：手机 / PC **不需要**能访问朋友服务器（也不挂其 VPN）——机器人与本地的唯一通道是 GitHub，两边各自与 GitHub 同步即可闭环。

## 能力边界（用户已确认）

| 能力 | 允许 | 实现 |
|------|------|------|
| 读取 | ✅ 任意笔记 / 搜索 / 系统健康汇报（读 `_告警摘要.md` 等） | GitHub MCP 读 API |
| 写入 | ❌ 仅 `01_内容系统/系统/inbox/`（命名 `微信-YYYYMMDD-HHmm.md`） | MCP 写 API + 技能层沙箱约束 |
| 修改既有笔记 / 选题池 / 观点 | ❌ 一律拒绝 | 技能指令 |

- 收件箱约定与处理流程：[[01_内容系统/系统/inbox/README.md]]
- 机器人写入的内容每天随同步回到本地，确认后由用户/本地流程移出 inbox。

## 安全设计（三层防线）

1. **GitHub 侧**：细粒度 PAT 只授权 `VerticalFall/obsidian-vault` 单仓库（Contents 读+写）；不授其他任何仓库/权限；
2. **技能层沙箱**：写入目标路径必须以 `01_内容系统/系统/inbox/` 开头，否则拒绝（部署后做负测试验证）；
3. **同步侧冲突保护**：`sync-vault.ps1` 本地为权威，冲突中止不覆盖（已验证）。

> 诚实标注：GitHub MCP 的写入权限是仓库级的，无法在 GitHub 侧限制到 `inbox/` 路径——"写仅 inbox"是技能层（提示词级）约束，不是代码级硬沙箱。若日后需要硬沙箱，再自写 Python 工具插件（按 CowAgent 工具开发文档，见部署指南）。

## 风险清单

- **个人微信封号风险**：微信渠道基于第三方协议 hook，违反微信用户协议——用户已知情选择；备选：企业微信官方渠道（文档随时可切换）；
- **Agent 模式 token 消耗**：比普通对话耗 token，按量计费；
- **朋友服务器可信环境**：CowAgent 官方提示"仅在可信环境部署"；凭证最小化 + 收件箱沙箱缓解；
- **PAT 保管**：只放在服务器 `~/cow/mcp.json`，泄露则立即到 GitHub 撤销重建。
