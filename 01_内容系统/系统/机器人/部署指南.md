# CowAgent 部署指南（微信 AI 机器人 ↔ GitHub 知识库）

> 适用范围：P-20260808-01。执行人：用户（朋友服务器在其手中），本指南把每一步落到可照做的程度。
> 前置调研：CowAgent README + 官方文档 docs.cowagent.ai（2026-08-08 核实）。
> 模型：**DeepSeek V4 Flash**（用户指定）。

## 阶段 0 · 前置确认（先在朋友服务器上确认）

- [ ] 服务器出站可达：`github.com` / `api.github.com` / `api.deepseek.com`（`curl -I` 各试一次；内网环境若有代理需先配好）
- [ ] 满足一种部署方式：Docker（推荐）或 Linux 一键脚本；磁盘 ≥ 5GB，内存 ≥ 2GB
- [ ] 服务器侧确认 CowAgent 的**可信环境**前提（官方提示"仅在可信环境部署"）——这台机器是你朋友的，评估后确认继续

## 阶段 1 · 部署 CowAgent（二选一）

**Docker（推荐）**：
```bash
curl -O https://cdn.link-ai.tech/code/cow/docker-compose.yml
docker compose up -d
```

**一键脚本**：
```bash
bash <(curl -fsSL https://cdn.link-ai.tech/code/cow/run.sh)
```

启动后本机访问 `http://localhost:9899` 进入 Web 控制台；服务器远程访问时按官方文档把 `web_host` 设为 `0.0.0.0` 并设置 `web_password`（安全组放行 9899）。

## 阶段 2 · Web 控制台配置

1. **模型**：控制台 → Providers → DeepSeek：填 API key，模型选 **`deepseek-v4-flash`**（README 确认支持 flash/pro；控制台配置，无需手改文件）
2. **微信渠道**：控制台 → 渠道 → WeChat，按官方文档 https://docs.cowagent.ai/channels/weixin 完成登录接入（个人微信的登录方式以该文档页为准；扫码/协议细节部署时核实）
3. 完成一条测试消息，确认对话通（先不接 GitHub）

## 阶段 3 · GitHub 集成（MCP）

### 3.1 创建细粒度 PAT（在你自己的 GitHub 账号）

1. GitHub → Settings → Developer settings → **Fine-grained personal access tokens** → Generate new token
2. **Repository access**：Only select repositories → `VerticalFall/obsidian-vault`
3. **Permissions**：Contents = **Read and write**（其余全不授：Administration / Actions / Secrets 等一律 No access）
4. 生成后只复制一次，保存到服务器（见下）

> 为什么不给 repo 全量 token：细粒度 PAT 把机器人泄漏面钉死在单个仓库；泄露后只需撤销这一个 token。

### 3.2 配置 mcp.json

在服务器 CowAgent 目录（Docker 部署为宿主 `./cow/`，即挂载点；非 Docker 为 `~/cow/`）创建 `mcp.json`：

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "<你的细粒度PAT>"
      }
    }
  }
}
```

CowAgent 读取 `~/cow/mcp.json`，改完自动热重载（无需重启）；启动日志出现 `[MCP] Server 'github' load` 即加载成功（失败会打 `load failed`）。

验证：在微信里问机器人"读一下 `01_内容系统/系统/inbox/README.md` 的内容"（告诉它仓库是 `VerticalFall/obsidian-vault`、分支 `vault-backup`）。

## 阶段 4 · 收件箱写入技能（沙箱约束）

写入的路径约束是技能层规则，用 CowAgent 内置 **skill-creator** 创建（控制台对话输入以下提示词）：

> 创建一个技能：调用 GitHub 工具的写文件能力时——目标仓库 `VerticalFall/obsidian-vault`、分支 `vault-backup`；**写入路径必须以 `01_内容系统/系统/inbox/` 开头**，文件名格式 `微信-YYYYMMDD-HHmm.md`；任何写入 inbox 之外路径的请求（包括修改既有笔记、选题池、观点）一律拒绝并解释原因；读取任意路径不受限。提交信息格式：`bot: <内容摘要>（YYYY-MM-DD HH:mm）`。

创建后在技能列表确认生效。

## 故障速查

- **MCP 没加载**：看启动日志 `[MCP] Server 'github' load failed`；检查 PAT 权限（Contents Write 是否授）、网络出站；
- **机器人写不进**：先试阶段 3.2 的读取验证区分"读取不通"与"写入被拒"；写入被拒=技能约束生效（符合预期），写入报错=看 PAT 权限；
- **同步不到本地**：查本地 `01_内容系统/系统/scripts/sync-vault.log`；远程文件应在 vault-backup 分支（别推到 main——每日日报的 GitHub Action 会覆盖它）；
- **PAT 泄露**：GitHub 立即撤销该 token，重建后改 `mcp.json`。
