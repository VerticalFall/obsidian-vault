# 公众号写作

> 核心原则：**做一个平实有料的朋友，不做 AI 在输出信息。**
> 生产链路：选题 → 读角度 → 两步调研 → 写作 → 四层自检 → 事实核查 → 存档登记。
> 风格规范出处：`obsidian知识库框架.md` §④「写作：去 AI 味 + 四层自检」；立场红线出自 `_观点.md` R1-R5。

## 流程

### 1. 选题
- 从 `01_内容系统/知识库/每日日报/_选题池.md` 🔥 高优先级区选**有感觉**的选题（有共鸣、有话想说才写，不为凑数）。
- 用户指定了选题 / 主题时，直接用它。

### 2. 读路由角度
- 读对应日期 `_路由/YYYY-MM-DD.md` 中该选题的「选题角度 / 框架 / 观点信号」。
- 角度是出发点，不是紧箍咒；写作过程中以真实感受为准。

### 3. 两步调研（写作前必做，不做不开写）
1. **读原文 / 原始报道**：回到信源本身，不看二手摘要转述。
2. **搜外围**：同类事件、历史对照、多方观点——让文章有纵深感。

### 4. 写作
- 平实语气、具体数字、反直觉开头、三段式结构。
- 自查禁用词 / 模板腔：对照框架 §④ 的规范；禁词表尚未落地的条目，按"像朋友说话"标准自检。

### 5. 四层自检

| 层 | 检查什么 | 过不了怎么办 |
|----|----------|-------------|
| L1 硬规则 | 禁用词表 / 模板开头 / 三段式逐条过 | 改到全过再进下一层 |
| L2 风格一致 | 语气像朋友，不像 AI 报告 | 重写 AI 腔段落 |
| L3 内容质量 | 论点 / 论据 / 框架成立 | 补调研或删弱论证 |
| L4 活人感 | 会不会有人愿意转给朋友看 | 回到第 1 步重想选题或角度 |

### 6. 事实核查五条红线
1. 日期区分「宣布」与「执行」
2. 不给信源加戏（不夸大原意）
3. 原话必须可查（出处明确）
4. 区分事实与观点
5. 有不确定就写不确定

### 7. 存档登记
1. 先存 `01_内容系统/输出/公众号/{文章名}.md`
2. 再在 `_选题池.md` 的 ✅ 已发布区登记

## 立场红线（`_观点.md` R1-R5）

- 不预测股价 / 不给买卖建议
- 不用民族情绪 / 胜负叙事代替产业分析
- 不把单一公司 / 事件放大为整个行业结论
- 不写"AI 太可怕"式恐慌、不参与"AI 觉醒"式空洞讨论
- 不讲"三句话讲完"的简化故事，愿意为复杂付出解释成本

## 交付前自查

- [ ] 两步调研确实做了（能说出读了什么原文、搜了什么外围）
- [ ] 四层自检逐层通过
- [ ] 五条事实核查红线逐条过
- [ ] 存档 + 选题池登记完成

## 红线

- **未调研不写、未自检不交付。**
- 观点不能超出 `_观点.md` 的立场边界；突破边界必须先与用户确认。
- 文章定稿后先存档再展示，不经手"未落盘"的终稿。
