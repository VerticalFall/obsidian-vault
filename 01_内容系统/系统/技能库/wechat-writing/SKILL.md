# 公众号写作 · 财经分析

> **定位**：用经济学与历史框架拆解前沿信息的分析者。
> **核心承诺**：读者读完应该觉得"这个人会想事情"，而不是"这个人读过书"。
> **分析内核**：`references/框架内化.md` —— 12 本书提炼出的判断工具箱。**正文里不出现书名。**
> **风格出处**：`obsidian知识库框架.md` §④；立场红线出自 `_观点.md` R1-R5。

## 一、四条不妥协的原则

1. **数字化**——具体数字优先于形容词。不说"大幅增长"，说"从 2,500 涨到 30,000"。
2. **可追溯**——每句话要么有出处，要么明确标为我的判断。不靠模糊归因制造权威感。
3. **有边界**——**每篇至少一处明确说"这里我不确定"或"这个判断可能错在 X"**。没有边界的分析，读者会当成推销。
4. **不站队读者**——不预测股价、不给买卖建议（`_观点.md` R1）。"我确实不知道，知道了也不会说。"

## 二、生产链路

```
选题 → 读路由角度 → 两步调研 → 定骨架 → 写作 → 四层自检 → 事实核查 + 差量核对
  → 展示给用户 → 用户确认 → 存档 → 选题池登记
```

**注意**：最后三步不可颠倒。原技能写的是"先存档再展示"，与 `CLAUDE.md` 内容红线（公众号正文修改须经用户确认）冲突，**以红线为准**：先给用户看，确认后才落盘。

## 三、选题

- 从 `01_内容系统/知识库/每日日报/_选题池.md` 🔥 区挑**有感觉**的（有共鸣、有话想说才写，不为凑数）。
- 用户指定了选题就直接用。
- **选题自检四问**（挑不出来时用）：
  1. 有**矛盾**吗？同一件事出现两种读法（公司说好、市场说坏）？
  2. 有**数字落差**吗？一个具体数字能撑起整个故事？
  3. 有**时间对照**吗？历史上有同构样本可以做尺子？
  4. 有**具体细节**吗？一个反直觉的小事实，比宏大叙事更有力？

## 四、素材调研（不做不开写）

### 1. 读原始信源

回到 `X-Tweets/`、`AI-HOT/`、`TrendRadar/`、`FollowBuilders/` 里那条**原始条目**，不看路由日志的二手摘要。

原始信源常比摘要厚得多——财报电话会的问答记录、未删节的推文、带具体数字的完整段落，都在里面。

### 2. 搜外围核验

用 `web_search` / `web_fetch` 补三样：
- **硬数字**：营收、增长率、份额、时点——把道听途说换成可核对的数
- **历史对照**：同类事件在前几轮周期怎么演
- **多方观点**：尤其是反方，用来写"对立配对"

### 3. 框架匹配

想这件事该用哪把尺子。对照 `references/框架内化.md` §一~§三，找出能支撑论证的 1-2 个框架——**不是找一本书贴上，是找一套判断方法**。

## 五、内化写法（本文档最重要的一节）

### 铁律：正文不出现书名

不写"正如《聪明的投资者》所说"，不写"这让人想起市场先生"，不写"格雷厄姆告诉我们"。

**贴标签式的引用是 AI 味的重灾区**——它用一个名字代替了论证，读者看到的不是思考，是装饰。这与 `humanizer` 的"借权威"是同一类毛病。

### 三种写法对照

**① 判断框架 → 长在论证里**

| | |
|---|---|
| ❌ 贴标签 | "《聪明的投资者》告诉我们，市场先生因 CPI 恐慌报价，而台积电的供需缺口依然巨大。" |
| ✅ 内化 | "同一天里，一家公司说需求远超供应，市场说 AI 是泡沫。两句话都对，因为它们算的不是同一件事——一个在算下个季度的产能，一个在算下个季度的资金成本。" |

**② 历史对照 → 当尺子用，不当典故选**

| | |
|---|---|
| ❌ 贴标签 | "按照《债务危机》的周期模型，我们现在处于去杠杆阶段。" |
| ✅ 内化 | "这类融资模式有个共同前提——资产价格得一直涨。价格一停，抵押品就撑不住债务。2008 年的美国、1990 年代的日本、眼下的地方债，骨架是同一副。" |

**③ 认知偏误 → 用来解释现象，不用来教训读者**

| | |
|---|---|
| ❌ 贴标签 | "这是典型的叙事谬误，卡尼曼早就证明过。" |
| ✅ 内化 | "事后看，这一切都像必然——因为我们已经知道结局了。当时站在那个岔路口的人，看到的是一堆互相矛盾的信号。" |

### 唯一例外

`_观点.md` 的 V 编号（如"印证 V2"）可以出现在**给用户看的说明里**，但**不进正文**。正文是给读者看的，V1-V7 是你自己的内部编号，读者不知道那是什么。

### 对立配对（提升说服力最有效的一招）

`references/框架内化.md` §四 列了 6 组内置张力（可预测性、价值可否度量、制度 vs 周期、结构 vs 个体、模型 vs 直觉、叙事 vs 基本面）。

**用法**：先各自讲透，再给**分界条件**——"在什么条件下前者成立、什么条件下后者成立"。**分界条件才是你的贡献**，不要在同一段里和稀泥。

## 六、文章骨架（四种）

| 骨架 | 适用 | 结构 |
|---|---|---|
| **两套账本** | 基本面与市场背离 | 事实 → 市场在定价什么 → 两个时间尺度 → 读者能带走的判断尺 |
| **周期定位** | 行业狂欢或崩塌 | 历史标尺 → 今天的位置 → 哪里像、哪里不像 |
| **信号群** | 多条弱信号指向同一趋势 | 分散信号 → 串起来 → 温差本身即信号 |
| **制度结构** | 政策、规则变化 | 表面事件 → 制度设计 → 谁受益谁承压 |

**开工前先定骨架**，写到一半再想结构必然松散。

## 七、写作技法（从成熟中文长文写作里取的，已验证的部分）

- **开头从具体事件切入**。拒绝"在当今 AI 快速发展的时代"。第一句话要让人产生"然后呢"的冲动。
- **扣主线句**——每偏出去（举例、科普、插叙）之后，用一句话拉回主线，**高频出现**。这是防读者走神最有效的一招。
- **前后呼应**——开头埋的意象或钩子，结尾以变体回来。这让文章像一个作品，而不是一堆信息。
- **升降番**——多个案例对比时，最弱的放前面，最炸的留最后。
- **一处句式断裂**——关键节点用一句话独立成段，制造停顿和重量。
- **反向论证**——先满足读者预期再打破。语气是"我也曾经这样想"，不是"你们都错了"。
- **知识是聊着聊着顺手掏出来的**，不是"下面我来科普一下"。引用历史或研究时，要像自然想起，不像特意去查。
- **升维要有来路**——从具体事件连到更大的历史或文化参照时，必须是"聊着聊着自然想到"，硬凑的升华比不升华更难看。

**不取的**：不写口癖式口语（"太特么赤鸡了"）、不假装亲历（"我买了 9.9 的……"——没真做就别写）、不加客服式结尾、不写"N 条心得"式数字编号结构。

## 八、中文化检查（去 AI 味）

### 硬约束：改写不得引入新事实

这是最容易犯、后果最严重的错误：

- **不许新增**原文没有的事实、数字、名字、日期、引文、来源
- **不许改变确定程度**："可能"不能写成"确定"，"计划"不能写成"已完成"，"相关"不能写成"因果"
- **不许丢失信息**：否定、比较对象、范围、条件、时间、完成状态、归因，一个都不能掉
- **不许把无来源的权威背书改成自己的事实断言**

### 改写后差量核对（四项）

1. 每个新增的具体信息，能在原文或调研材料里找到吗？**找不到就撤回。**
2. 独立信息、否定、限定、时间、范围、归因是否完整？有没有把"可能"写成"确定"？
3. 调整句式或列表后，有没有丢失内容或添出新项目？
4. 归因是否还挂在原来的主体上？

### 中文高频问题（自查清单）

- **"的"字连珠**——超过 3 个"的"的修饰链要拆
- **"进行 + 动词"**——"进行测试" → "测试"
- **四字格排比堆砌**——"稳定可靠、快速响应、易于维护" → "运行稳定、响应快，也方便维护"
- **"随着……的发展"式开头**——背景没有独立信息时直接删
- **套话收尾**——"让我们拭目以待""未来可期"全删
- **意义拔高**——"标志着新时代的到来"这类没有独立内容的套话
- **空洞归纳**——"综上所述""总而言之"
- **同义替换堆叠**——"该技术……这一方案……此项创新……"（同一事物换着说法）
- **句式均匀**——连续 3 句以上长度相近就是节奏呆板，需要长短交替
- **客服腔**——"好问题！""希望这对您有帮助！"
- **过度谦虚填充**——"以上只是个人浅见"

## 九、标点与格式

- 中文正文用中文标点，**冒号、破折号、双引号都允许，但不滥用**。
- 双引号统一用中文引号，不用英文直引号；需要强调时也可以用「」。
- 段落要短，很多时候一句话就是一段。重要观点前后留白。
- **不用 markdown 小标题切割**（除非确实是分条目的方法论文章）。板块之间用口语化转场句衔接。
- 需要配图的位置标注"图片"即可。

## 十、四层自检

| 层 | 检查什么 | 过不了怎么办 |
|----|----------|-------------|
| **L1 硬规则** | 第七章"不取的"清单、第八章中文高频问题、字数与段落 | 改到全过再进下一层 |
| **L2 风格一致** | 语气像分析者，不像研究报告；有无扣主线句；节奏有无长短交替 | 重写 AI 腔、报告腔段落 |
| **L3 内容质量** | 论点/论据/框架成立；**正文是否混入了书名**；边界纪律是否执行（至少一处说"不确定"） | 补调研或删弱论证 |
| **L4 活人感** | 会不会有人愿意转给朋友看 | 回第 2 步重想选题或角度 |

**L1 必须全过。L2/L3 的检查结果要写进交付说明。**

## 十一、事实核查五条红线

1. **日期区分「宣布」与「执行」**——宣布的计划不等于已发生的事实
2. **不给信源加戏**——不夸大原意，不把"注意到"写成"警告"
3. **原话必须可查**——引号内的话要能指到具体出处
4. **区分事实与观点**——我的分析和事实段落要分开
5. **有不确定就写不确定**——标为"预计""据 XX""尚不清楚"

## 十二、立场红线（`_观点.md` R1-R5）

- 不预测股价 / 不给买卖建议
- 不用民族情绪 / 胜负叙事代替产业分析
- 不把单一公司 / 事件放大为整个行业结论
- 不写"AI 太可怕"式恐慌、不参与"AI 觉醒"式空洞讨论
- 不讲"三句话讲完"的简化故事，愿意为复杂付出解释成本

## 十三、存档与登记

1. **先展示**草稿给用户（正文 + 事实核查说明 + L1-L4 自查结果）
2. 用户确认后，存 `01_内容系统/输出/公众号/{文章名}.md`
3. 在 `_选题池.md` 的 ✅ 已发布区登记

> ⚠️ **登记不能漏**：健康检查第 9 项「写作产出」读的就是 ✅ 已发布区的最近日期。只发文不登记，会触发"写作产出停滞"的误报。

## 交付前自查

- [ ] 两步调研确实做了（能说出读了什么原始信源、搜了什么外围）
- [ ] **正文全文搜索过书名，零命中**
- [ ] 至少一处明确的"不确定"或"可能错在"
- [ ] 四层自检逐层通过（L1 全过）
- [ ] 五条事实核查红线逐条过
- [ ] 改写差量核对四项过（无新增事实、无确定性漂移）
- [ ] 用户已确认
- [ ] 存档 + 选题池登记完成

## 红线

- **未调研不写、未自检不交付。**
- **正文不出现书名**——框架要内化，不要贴标签。
- 观点不能超出 `_观点.md` 的立场边界；突破边界必须先与用户确认。
- **未经用户确认不落盘**（依据 `CLAUDE.md` 内容红线，优先于本技能原"先存档"规则）。
