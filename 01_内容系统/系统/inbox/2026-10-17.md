# 2026-10-17

## 一篇文章变成一个能跑的工具

今天洛哥丢来一篇公众号文章：《研报速读 Skill —— 1 小时研报 5 分钟读完》，作者「思辨的人」，公众号「凌晨四点的架构师」，金融投研系列第 1 篇。

链接：https://mp.weixin.qq.com/s/EbQCsw5WgQR6xOYc9oc_dw

要求很直接：把它做成 skill。

## 文章讲的是什么

**问题**：券商研报 30–100 页，人工读一遍要 1 小时（读 30 分钟 + 抓重点 20 分钟 + 写笔记 10 分钟），而且看完忘 80%。四个根因：篇幅长、重点散、数据多、无结构。

**解法**：不是"写个更好的 prompt"，而是做成 Skill —— 1 个 SKILL.md + 5 类规则 + 10 段结构 + 6 步工作流。

**prompt 与 Skill 的分水岭**（这是原文最值钱的一句）：

| 维度 | 普通 prompt | Skill |
|---|---|---|
| 读什么 | AI 反问，来回 3 轮 | 10 段结构固定，0 轮 |
| 数据在哪 | 用户手动复制表格，AI 仍缺 3 个指标 | 脚本从 PDF 自动抽 |
| 输出格式 | 这次 5 段下次 8 段，无法对比 | 规则统一，可横向对比 |
| 合计 | 10 轮对话 + 30 分钟 | 1 句指令 + 5 分钟 |

> **prompt 是一次性对话，Skill 是可复用资产。差别不在模型能力，在结构沉淀。**

**5 类规则**：结构（10 段固定顺序、每段 1–3 句、总长 500–800 字）、数据（必抽营收/净利/毛利率/ROE/PE/PB，必带单位+同比+环比）、估值（至少 1 种方法，必给当前估值+合理估值+偏差%+目标价+评级）、风险（行业/政策/公司/估值 4 类全覆盖）、输出（5 段格式）。

**数据规则的原话值得记**："营收 100" 是废数据，"100 亿元（+20% YoY）" 才有效。

**五个坑**：数据失真（不给单位）、估值不严谨（目标价凭感觉）、风险遗漏（只报 1 类）、评级机械（永远"买入"）、上下文割裂（业绩好却给减持，不解释）。

## 落地时做的判断：不照抄

原文的示例代码是"示意级"，直接抄会坏：

1. `split_10_sections` 用 `text.find(kw)` 截 500 字符 —— 遇到正文第一个"估值"就停，段落严重重叠
2. 正则只认整数 `\d+` —— "25.5%" 直接失配
3. `print("用法: python research_runner.py ")` —— 路径参数都丢了

更根本的问题：**它把抽取和判断混在一起**。正则抽完就直接拼摘要，等于没有判断层。LLM 真正的价值在"评级理由是否自洽、业绩与结论是否矛盾"，这部分原文没做。

所以按方法论重写，做了这几处：

- `pdfplumber` + 分页标记 `<<<PAGE n>>>`，保留回溯原文的能力
- 段落定位改「短行 + 关键词」双条件，避免正文出现"估值"二字就误判
- 风险段加**截断保护**：遇"催化剂/评级/免责声明"就停（实测修掉了"公司风险"误吃催化剂内容的 bug）
- 单位兜底表：`毛利率→%`、`PE→x`，解决"毛利率：25"的歧义
- **缺失段一律 N/A + 明示"原文未提及"，绝不编造** —— 原文说"不遗漏"，但遗漏的判断权在原文，不在模型

## 产出

`skills/research-report-reader/`：

- `SKILL.md`（163 行）：5 类规则、10 段结构、6 步工作流、避坑清单、模板
- `scripts/extract_report.py`（256 行）：PDF 解析 + 10 段定位 + 指标抽取 + 风险归类 → 骨架 JSON
- `scripts/render_summary.py`（151 行）：骨架 JSON → 5 段速读摘要

环境限制也顺手解决了：容器里没系统解析库、没 root 权限，用用户级 `pip install pdfplumber` 绕开；脚本设计成"有库用库、无库降级提示"，纯 TXT 可加 `--text` 免装。

**测试**（模拟研报）：10 段全部识别、9 个指标全部抽出、4 类风险全部归类。修了两处：风险块范围收窄、毛利率/ROE/PE 单位补全。`quick_validate.py` 验证通过，真实 PDF 也跑通了。

**本地用法**：

```bash
pip install pdfplumber
python extract_report.py 研报.pdf -o sk.json
python render_summary.py sk.json -o out.md
```

页数多的 PDF 建议先 `--pages 1-20`。

## 一个能带走的范式

这套「规则 × 结构 × 工作流」不限于研报。任何"长文档 → 固定结构摘要"都能套：

- **财报速读**：换成财务三大表指标
- **招股书速读**：换成业务/募投/风险/估值段
- **合同审查**：换成条款类型/责任分配/风险点
- **论文速读**：换成 RQ/方法/数据/结论/局限

判断一个场景值不值得做成 Skill 的三问：

1. 输出结构固定吗？
2. 数据能确定性抽取吗？
3. 要反复做吗？

三者皆 yes 才值得沉淀。这条比文章本身更有用 —— 它把"什么时候该做 Skill"变成了一个可以立刻回答的问题。
