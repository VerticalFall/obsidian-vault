# 韭菜指数 v4.0 —— 生产规范（当前生效版）

> 本文件是韭菜指数项目的**唯一权威规范**。旧版 SKILL（v1.3 散户吃瓜指数周报框架）已废弃，仅存于 `_archive`。
> 每期报告**从本文件夹的模板起步**，禁止从上一期报告复制——上一期永远是最大路径依赖源。

## 一、产品线（三条，午报线已砍）

| 产品线 | 发布时点 | 字数预算（可见中文） | HTML 模板 |
|---|---|---:|---|
| 上午版 | 11:35 后（上午收盘快照） | **≤ 1,500** | `references/template-上午.html` |
| 全天版 | 15:10 后（全天收盘） | **≤ 4,500**（原版全结构格式，10/16 精简版实测 4,806） | `references/template-全天.html` |

全天版区块（顺序固定，全部保留）：头部 → ①五温度计 → ②TOP10 十张完整卡 → ③前六大深吃瓜（双列彩条卡 + L1~L5 五级分布条）+ 韭菜浓度普查表 → ④国家队资金动向（etf-verdict 四条证据 + 16只ETF对账表 + SVG条形图 + 四维验证表）→ 尾盘时间轴 → ⑤主力资金双栏 → ⑥核心矛盾 → ⑦明天预判三情景 → 数据说明+免责。

**版式基准**：1160px 宽屏双列版式（深吃瓜双列、温度计五列、ETF 表全宽），760px 以下响应式降级。排版以 10/16 原版为美学基准，不做窄版自创。

字数预算是**硬约束**：写完自检（剔除 style/script 后统计中文字符），超了先砍 L3 推理过程，再砍 L2 论据，**永远不砍 L1 结论与数据**。

## 二、三层信息法（HTML 瘦身的核心规则）

| 层 | 内容 | 去向 |
|---|---|---|
| **L1 结论层** | 数字、标签、环比箭头、断症一句话 | 留 HTML（PNG 主图层） |
| **L2 论据层** | 每卡最多 2 条硬证据（带数据来源） | 留 HTML |
| **L3 过程层** | 推理过程、多空论据展开、来回对照 | **移出 HTML**——写进数据 MD 存档，或直接删 |

「内容不缺失」的兑现方式不是忍痛删，是**换形态**：80 字论述 → 一个箭头 + 一个数字 + 一个标签。

### ⛔ 信息结构不可砍清单（砍字只砍论述，永远不砍结构）

1. **TOP10 十张完整卡片**——7-10 名不得降级为一行式
2. **深吃瓜卡内 L1~L5 五级分布条**（五色块各带 pct）必须完整排列
3. **韭菜浓度普查总表**（含分布条形图）
4. **国家队资金动向**：etf-verdict 四条证据 + 16只 ETF 对账表 + SVG 条形图 + 四维验证表
5. **尾盘时间轴 + 明天预判三情景**（预判即下期对答案的输入）

超字数预算时的砍字顺序：① 先砍 disc 口径段与论据罗列 → ② 再压缩 TOP10 desc → ③ 结构性数据永远不砍。

各区块字数上限：
- 温度计 t-desc：≤ 14 字
- 围观榜 desc：≤ 55 字（数字+断症+可选一句金句）
- 深吃瓜 dc-data 每行：≤ 35 字
- 深吃瓜断症 dc-ding：≤ 80 字（灵魂所在，允许带情绪和金句，必须点出 L1+L2 浓度）
- L5 侦探结论：≤ 80 字
- det-verdict（国家队结论）：≤ 120 字，含四条证据
- 核心矛盾每条：≤ 80 字
- 情景预判每条：≤ 60 字

## 三、五支温度计（唯一打分体系）

| 温度计 | 回答什么 | 锚定输入（全部可复算） |
|---|---|---|
| 市场热度 | 市场整体活不活跃 | 成交额 vs 近20日均值、涨跌家数比 |
| 赚钱效应 | 今天持仓的人赚不赚 | 上涨家数占比、涨停家数 vs 近20日均值、连板高度 |
| 讨论热度 | 人声鼎沸还是冷清 | **成交额环比**（缩量=降温、巨量=过热）、涨停家数 |
| 恐贪情绪 | 散户追高意愿 | 封板率、涨停家数、连板高度 |
| 风险偏好 | 资金防御还是进攻 | 进攻型板块（券商/科技/军工）vs 防御型（银行/白酒/电力）当日涨幅差 |

**铁律**：
1. 分数必须按 `references/scoring-v4.md` 的锚点表**复算得出**，禁止凭语感打分。
2. 三支情绪温度计（讨论热度/恐贪/风险偏好）**必须独立**——不得用同一个依据（如都拿"缩量"说事）。
3. 每支温度计 HTML 里必须带 t-desc（≤14字），说明分数从哪来。

## 四、数据规范（有效性与辩证性）

### 4.1 数据源分级

| 级别 | 来源 | 用途 | 规则 |
|---|---|---|---|
| **硬数据** | 通达信（tdx-connector）、财联社 | 行情、涨停、资金流、成交额 | **必须标注采集时间**（如"10/16 11:30 快照"） |
| **软数据** | WebSearch 抓股吧/雪球/微博/评论区 | 散户发言、情绪判断 | 必须标**样本数 + 来源平台** |
| **排除数据** | 股吧/自媒体单帖的未经核实数字 | — | **零容忍**——个人帖数字不当事实弹药，须交叉验证官方/券商口径后才可用 |

### 4.2 软数据可信度门槛

- 散户发言样本 **< 15 条** → 该板块标注"数据不足"，L1-L5 分布不下结论。
- 温度计若某锚定输入缺失（如封板率查不到）→ 分数照算，但在数据说明里标注"该输入缺失"。
- **反路径依赖**：每轮采集用当天新搜索，禁止沿用上一期的板块清单和结论——"今天什么热就记什么"。

### 4.3 环比基准

- 上午版环比 → 昨日**全天**。
- 全天版环比 → 昨日全天；周五全天环比 → 周四全天。
- 周报环比 → 上一期周报（整周口径）。
- 环比标签统一：↑红 / ↓绿 / 持平灰（A 股口径，涨红跌绿）。

## 五、验证闭环（辩证性的落地机制）

```
上午版「下午盯什么」留 3 个验证点
        ↓（当天）
全天版「验证点对答案」：预判 vs 实际 → ✓/✗/部分
        ↓（周六）
周报「本周验证命中率」：统计 5 天命中率 + 被打脸的点单独复盘
```

**铁律**：
1. 全天版**必须**含「验证点对答案」区块——表格化（预判→实际→判定），每行 ≤ 30 字。
2. 被打脸（✗）的验证点不得悄悄略过，必须写一句"为什么错"。
3. 周报必须给出本周命中率数字（如 11/15 = 73%）。
4. 命中率连续两期 < 50% → 在周报里公开检讨打分体系，考虑调整锚定公式。

## 六、工作流（每期五步）

1. **采集**：通达信查硬数据（指数/涨停/成交额/资金流/板块涨幅）+ WebSearch 采散户发言（每板块 ≥ 2 轮搜索，标样本量）。
2. **打分**：按 `references/scoring-v4.md` 锚点表复算五支温度计。
3. **填模板**：复制对应模板到当日输出文件夹，替换 `{{占位符}}`，遵守字数预算与三层信息法。
4. **自检**：中文字数统计 → 超预算先砍 L3；三支情绪温度计依据是否独立；数据来源/时间是否标注。
5. **出图**：HTML → Playwright 截图 → PNG 长图（沿用当日文件夹内截图脚本）。

## 八、通用铁律

1. 红涨绿跌（A 股口径），全报告统一。
2. 免责声明每期必带：娱乐化散户行为观察，不构成投资建议。
3. 视觉：纸质感配色 + 衬线/系统字体、纯 SVG 无 CDN、PNG 高清长图。
4. 标题必须含「当天最关键的对比/反转 + 具体数据」。
5. 主流板块热度下降也**不得合并**（光模块和半导体各自独立列条）。
